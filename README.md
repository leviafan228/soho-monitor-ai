# SOHO Monitor AI — інтелектуальна система моніторингу SOHO-маршрутизаторів

Вебсистема для дистанційного моніторингу домашніх і малих офісних (SOHO) маршрутизаторів.
Система цілодобово перевіряє доступність роутера, збирає телеметрію, **визначає причину втрати
зв'язку** (відключення електроживлення, аварія провайдера, збій самого роутера), **виявляє деградацію
каналу** до повної аварії і надсилає пояснення та рекомендації в Telegram.

Статус: робочий прототип (протестований на роутерах TP-Link та Asus), розвиток до інтелектуальної ІС
у межах лабораторних робіт 3–7 з дисципліни «Інженерія та верифікація інформаційних систем».

## Можливості
| Функція | Як працює |
|---|---|
| Моніторинг доступності | опитування кожні 5 с, вимірювання затримки (TCP-connect до порту 80) |
| Діагностика за правилом | якщо доступний UPnP: `uptime + T_boot < downtime` ⇒ роутер перезавантажувався ⇒ знеструмлення |
| **ML-діагностика** | якщо UPnP вимкнено: логістична регресія за непрямими ознаками (тривалість, графік відключень, деградація перед збоєм, «сусіди» в зоні та в провайдера), F1-macro = 0.967 |
| **Детектор аномалій** | EWMA-норма затримки на кожен роутер; 5 аномалій з 10 (z > 3) ⇒ подія «деградація каналу» |
| Пояснення інцидентів | людською мовою + рекомендація власнику об'єкта |
| Сповіщення | Telegram: тривога, звіт після відновлення, деградація, регулярний звіт |
| Безпека | вхід (JWT), ролі viewer / operator / admin, аудит дій, обмеження спроб входу |
| Експлуатація | резервне копіювання з перевіркою, структурований лог, Docker |

## Архітектура
```
frontend/ (React)  ──REST + JWT──►  backend/ (Node.js, Express)  ──►  MongoDB
                                       │  ├─ services/monitor.js   — опитування, ознаки, детектор
                                       │  ├─ services/analyzer.js  — правило або ML ⇒ вердикт
                                       │  ├─ ml/classifier.js      — інференс моделі (model.json)
                                       │  └─ services/notifier.js  — Telegram
ml/ (Python, scikit-learn) ── навчання ──► backend/src/ml/model.json
```

## Швидкий запуск (локально)
Потрібно: Node.js ≥ 20, MongoDB ≥ 6 (локально або Atlas). Python 3.10+ — лише для перенавчання моделі.

```bash
# 1. Бекенд
cd backend
npm install
cp .env.example .env          # вкажіть MONGO_URI і JWT_SECRET (≥ 32 символи)
npm run seed:demo             # тестові користувачі та 3 симульовані роутери
npm start                     # http://localhost:5000/api/health

# 2. Фронтенд (в іншому терміналі)
cd frontend
npm install
npm start                     # http://localhost:3000
```

### Базові дії користувача
1. Увійти під одним з облікових записів.
2. Оператор: додати роутер (назва, IP, провайдер, зона електропостачання, тип).
3. Переглядати стан роутерів, графік затримки (червоні точки — аномалії) і журнал інцидентів.
4. Адміністратор: для симульованих роутерів запустити сценарій збою кнопками під графіком
   або скриптом `node scripts/demo-scenario.js` — і побачити вердикт у журналі.

## Можливі проблеми під час запуску
| Симптом | Причина та рішення |
|---|---|
| `JWT_SECRET має містити щонайменше 32 символи` | заповніть JWT_SECRET у `backend/.env` |
| `MongooseServerSelectionError` | MongoDB не запущена або хибний MONGO_URI |
| «Немає з'єднання з сервером моніторингу» у браузері | бекенд не запущений або REACT_APP_API_URL вказує не туди |
| CORS-помилка в консолі браузера | CORS_ORIGIN у `.env` має збігатися з адресою фронтенду |
| Немає повідомлень у Telegram | не задано TELEGRAM_TOKEN / TELEGRAM_CHAT_ID (система працює, сповіщення лише в лозі) |
| Порт 5000 зайнятий | змініть PORT у `.env` і REACT_APP_API_URL у `frontend/.env` |
